# macOS v0.1.0 发布后回归

基线为 `478657e`（`v0.1.0`）。实际验证主机为 macOS 27.0.1 arm64、Xcode 27.2。以下失败均在修改实现前由新增测试复现，再通过相应修复复验。

| 场景 | 基线行为 | 修复后行为 |
| --- | --- | --- |
| 选中单行源码按 Tab | 选区被缩进空格替换，源码丢失 | 缩进整行并保留选区，双编辑器均支持原生撤销／重做 |
| 选区末端进入下一行缩进空白后 Shift-Tab | 漏处理末行；选区端点计算错误 | 按原生半开区间覆盖行，分别映射选区起点和终点 |
| 在已有闭括号前输入同字符，但没有匹配开括号 | 直接跳过已有字符 | 只有当前括号栈匹配时才跳过；其余交给原生插入 |
| 在字符串开始前输入引号、在两个字符串之间退格 | 跳过字符串开引号；误删两个相邻字符串的边界引号 | 区分引号的开始位置和结束位置，只合并删除真正的空引号对 |
| `0xAB'CD` 后继续写代码 | 数字分隔符被误认作字符常量开头，括号补全失效 | 使用语言资源的数字规则识别完整数字 |
| 未闭合普通字符串后换行继续编辑 | 后续行持续被当成字符串 | 未转义换行结束未完成的普通字符串；转义续行和原始字符串仍保留字符串上下文 |
| CR 文件或 CRLF／LF 混合文件中回车 | CR 变成 LF，任意位置存在 CRLF 就全局选 CRLF | 使用当前行终止符，最后一行沿用前一行 |
| 重启恢复已被升级移除的默认 G++ 路径 | 仍指向旧可执行文件；全部卸载后也没有缺失提示 | 仅对发现配置管理目录内已不存在的版本路径重新解析；保留参数和限制，无可用 G++ 时显示缺失提示并禁止运行 |

G++ 回归使用独立临时目录模拟旧版本保留、升级移除、完全卸载和目录外自定义路径，未改变本机安装。真实 `bits/stdc++.h` 的 Core 编译运行用例继续执行。

Debug 完整 Swift 108 项与 Core 17 项通过。Release 专项 28/28 通过，覆盖编辑规则、双编辑器、G++ 和判题结果。原生窗口验证使用独立恢复文件，Input、Expected、Output 均可见，G++ 样例获得 AC，单行选择缩进保留源码，撤销后复跑仍为 AC。构建与严格签名检查通过。

日志位于 `out/macos/post-release-regression/`，包括 `editing-before.log`、`gcc-before.log`、`selection-before.log` 的原始失败，`swift-full.log`、`swift-release.log`、`core-tests.log` 和 `app-build.log` 的最终验证。一次原生测试夹具在视图尚未发出首次选区通知时设置了模型选区，造成测试并未真正选中原生文本；夹具改为操作已挂载文本视图，未在产品中增加等待或延时。

本轮修改提交到后续开发分支历史，不移动 `v0.1.0` 标签或替换其下载文件。Windows 10、macOS 26 最低系统、Intel、发布签名／公证和整应用性能仍不属于已通过项。
